# Partition and commit cleanup

Read current PR scope, source guidance, Decisions, complete feedback and the exact user's constraints. Read additions and private partition settings through scripts/config.py before proposing work. Defaults: 1,000 added lines; unrelated evacuation and related splitting each independently automatic/manual/disabled. After every published code change repeat the size assessment. Honor a whole-PR opt-out until explicitly re-enabled. Keep a declined proposal separate from disabling the entire PR. Apply exact conditional instructions and retain their source in the evidence-backed partition/retain choice.

For scope partitioning, separate unrelated work from required scope and split related work only along independently reviewable/testable boundaries. Automatic settings authorize guarded draft-PR publication when the caller authorized iteration; manual settings require concrete action-bound approval. Disabled modes retain that work. Prepare new branches from the verified default target, preserve dependency order and a recovery ref, validate that the combined resulting trees preserve intended work, create draft PRs and descriptions/cross-links, then remove source work with the original exact lease. Capture publication intent before each remote action and reconcile uncertain creation before another attempt. Never merge, create issues, or discard other agents' edits.

For cleanup, inspect the complete commit series from merge base to head against the final reviewed diff. Capture original head/tree, target tip, remote branch lease, ownership and a recovery ref before rewriting. Require a clean worktree and safe same-author ownership; stop for ambiguous authorship or branch ownership. Preserve coherent boundaries; split mixed commits, fold fixups into the commits they repair and reorder only when useful. A single coherent commit is valid. Do not rewrite merely to change commit count.

Draft messages using repository templates and recent human conventions; every line stays within 80 characters. Review boundaries/messages together, stopping at the first unchanged pass or five total passes. Retain remaining concerns after the cap. Validate relevant tests and exact final tree equality with the reviewed tree. Recheck target tip, still-published source head/lease and governing context before any push. Changed files require content review; history-only changes require head-specific CI/publication and history consumers to refresh. Use scripts/publish.py for authorized exact-lease pushes. A changed remote lease or target tip blocks publication pending reassessment.

Always return an assessment with outcome no_op or published, PR identity, reviewed/final head, reviewed/final tree, target tip, commit count, boundary reasons, validation, recovery refs and publication receipts. A no-op requires reasons for the whole series, not just an unchanged SHA. Do not claim the caller's iteration complete; return the verified domain result so it can check current coverage and CI within its retained budget.
