# Repository instruction sources

Follow all discovered repository instructions by default, within their documented scopes and host instruction priority. Explicit saved source overrides remain supported. Resolve PLUGIN_ROOT from this skill installation's plugin root. Before loading repository guidance for a skill, run `python3 PLUGIN_ROOT/scripts/instruction_sources.py --checkout REPO --repository HOST/OWNER/REPO show`. Use the same repository identity as the workflow and configuration request, including when reviewing a fork; pass it on subsequent source reads too. Without an explicit identity the helper uses the checkout's origin, or the exact requested directory when no origin exists, matching configuration requests. Source paths remain relative to the Git root. This read returns the effective policy (default or saved override), ready status, discovered sources with their paths, kinds and selection status, and host limitations. It creates no configuration or request history. Existing private settings and direct user instructions remain separate governing inputs.

## Default and explicit overrides

Without a saved override, use `{"mode":"all","include":[],"exclude":[]}` immediately. Do not ask the user to choose instruction sources, require onboarding or configuration-agent delegation, or save a default policy or configuration request. Existing users without a saved policy and legacy reset markers use this same default. Malformed saved policies remain errors rather than silently discarding an explicit override.

Use [dk-repo-onboard](../codex/skills/dk-repo-onboard/SKILL.md) when onboarding or a discovery refresh is requested. It inspects relevant sources and returns the structured report without an instruction-choice question. Ordinary workflow entry uses the read helpers directly.

An explicit request to change sources uses [dk-config](../codex/skills/dk-config/SKILL.md) and its existing configuration-request admission and recovery. Ask only for missing details of that requested override or an unresolved conflict. A settled request needs no extra approval. Use `read --source REPO_RELATIVE_PATH --discovery` to inspect unselected candidates as evidence when explaining a proposed override; excluded text does not become governing guidance merely by being read.

A value has `mode`, `include` and `exclude` fields, for example:

```json
{"mode":"human","include":["docs/contributor-guide.md"],"exclude":[".github/CONTRIBUTING.md"]}
```

`human` selects discovered human-facing sources, `all` selects all discovered sources, and `custom` selects only exact included paths. Explicit includes add files; excludes override mode-based selection. The include and exclude lists must be disjoint. Paths are repository-relative references, not shell commands or globs. New discovered sources follow the saved mode and exclusions; a custom selection does not adopt newly discovered files automatically. The choice is specific to the current repository, without user or upstream inheritance. Read the current inventory when resuming; apply the default or saved override without an initialization question.

Exclusions also apply to resolved aliases of the same source. Unsafe instruction symlinks remain unselected inventory entries so governing handoffs cannot reintroduce them; ordinary and discovery reads reject those links. An unsafe alias does not exclude its independently selected regular target unless the policy explicitly excludes that source or an alias. Handoff validation covers resources, instructions and inputs, including directory references containing excluded sources.

Git-ignored automation and contributor guidance participates in discovery and the saved selection too. Git ignore rules do not change the effective policy or exempt direct, alias or directory handoffs from source checks. Selected ignored files use the same content freshness checks as tracked guidance.

After onboarding, return the [structured discovery report](../codex/skills/dk-repo-onboard/SKILL.md#structured-discovery-report) to the user when onboarding was requested. List all discovered sources, rules with scope and provenance, repository facts, inspected settings/preferences, conflicts, gaps and completion. Excluded rules remain evidence only. Construct the report in memory; do not persist it or use it as a substitute for selected original sources. An explicit onboarding refresh uses the effective policy and reports current discovery without a source-choice question. Ordinary workflow entry does not repeat onboarding.

## Read, change and reset

Load selected files with `read --source REPO_RELATIVE_PATH`; ordinary reads reject unselected sources. Discovery reads remain available to explain a proposed change, with the same evidence-only boundary. Apply each file only within its documented scope. A saved source choice does not change the host's instruction priority, grant permission, or make every sentence in a selected source a repository-wide rule.

Inspect the current choice with `scripts/config.py --repository HOST/OWNER/REPO --checkout REPO show --section instruction-sources` or the source helper's `show`. Change it through `dk-config` using a repository-scoped `instruction-sources` set operation. Reset it using that domain's reset operation; reset restores the all-source default. The existing null-policy reset record remains readable as the default and does not block work or require reinitialization. Neither action edits upstream repository files, resets budgets or clears original analysis.

Pass selected original source references and the current choice to downstream skills, including external reviewer skills. A receiver checks current selection before consuming repository guidance. Do not reintroduce excluded files through a saved summary, copied instruction artifact, preference-admission context, original reviewer result or an old handoff. Preserve historical evidence as evidence; recapture governing inputs and refresh affected analysis when its source choice or selected content changes. Source exclusions do not erase independently supplied user instructions or independently admitted private settings. If a copied artifact cannot be traced to its governing sources, treat its applicability as uncertain and refresh the affected handoff rather than promoting it to current rules.

Task definitions bind the repository checkout and a digest of the selected choice and source contents. Task capture validates that binding before reuse or acceptance; a changed binding requires rebuilding the affected assignment and handoff, rather than merely replacing its fingerprint while retaining an opaque old summary. Keep cache keys, original results and unaffected siblings; invalidation requires affected work to be refreshed, not a blanket cache reset. Default-selected content uses the same freshness binding as an explicit all-source policy. Legacy cached guidance without that binding requires rebuilding affected assignments when instruction sources exist; original results and unaffected work remain intact. A checkout with no discovered sources and no explicit override retains its legacy fingerprint. Invalid policy/source evidence blocks applicable reuse.

## Host limitations

The host may have loaded repository or ancestor instruction files before a skill runs. dk-workflows cannot unload that context, override system/developer instructions or other higher-priority host rules, or prove that excluded text was never seen. Apply this source boundary before optional workflow reads and delegation wherever possible, and disclose any already loaded conflicting guidance. Explain the specific limitation to the user; do not claim that choosing human guidance disabled a host-enforced automation rule. Where the host cannot honor the requested exclusion, report the affected behavior as blocked or incomplete and explain that host-side instruction configuration must be changed by the user. Do not launch another Codex or Claude Code session as a workaround.

The helper inventories sources inside the checkout. Host-level and ancestor instructions remain subject to the host's own loading and precedence rules; disclose them when present rather than implying that an in-checkout inventory is complete host coverage. Configuration admission retains its ancestor `AGENTS.md` freshness checks independently of the optional in-checkout selection, so changes require fresh admission. Saved selection controls optional dk-workflows source adoption, not host security or instruction precedence.
