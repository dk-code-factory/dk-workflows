# Partition and commit cleanup

Read current scope, original guidance, Decisions, complete feedback and the user's exact constraints. Count added lines in the complete diff. Read private partition settings with `scripts/pr_config.py` before proposing work. The default threshold is 1,000 added lines. Moving unrelated work and splitting related work each have a separate mode: automatic, manual or disabled. Repeat the size check after every published code change.

Honor a whole-PR opt-out until explicitly re-enabled. Declining one proposal does not disable partitioning for the PR. Apply exact conditional instructions. Save their source with the reasoned decision to retain or split work.

For partitioning, separate unrelated work from required scope. Split related work only at boundaries that can be reviewed and tested independently. Automatic mode permits guarded draft-PR publication when the caller authorized iteration. Manual mode requires approval of the concrete action. Disabled mode keeps that work in the source PR.

Create branches from the verified default target. Preserve dependency order and a recovery ref. Verify that the combined resulting trees preserve the intended work. Create draft PRs with descriptions and cross-links, then remove the moved work from the source PR using its original exact lease. Save publication intent before each remote action. Reconcile uncertain creation before retrying. Do not merge, create issues or discard other agents' edits.

For cleanup, first resolve or verify [the effective commit policy](../commit-policy.md), including on direct invocation. Inspect every commit from merge base to head against the final reviewed diff. Before rewriting, save original head and tree, target tip, remote branch lease, ownership and a recovery ref. Require a clean worktree and safe ownership by the same author. Stop if authorship or branch ownership is ambiguous. Apply explicit grouping instructions within those safeguards. Without a configured policy, preserve logical boundaries, split mixed commits, fold fixup commits into the commits they repair, and reorder only when useful. One logical commit is valid. Without explicit grouping instructions, do not rewrite just to change the count.

Draft messages through `dk-commit-message` with the policy's message instructions, required repository templates and current user constraints. Explicit policies replace built-in stylistic defaults. Without explicit message instructions, use recent human conventions and limit each line to 80 characters. Review boundaries and messages together. Stop at the first unchanged pass or after five total passes. Report concerns left after the limit. Run relevant tests and verify that the final tree exactly matches the reviewed tree.

Before pushing, recheck target tip, published source head, remote lease and governing context. Changed files require content review. History-only changes require fresh CI and publication checks for the new head, plus refreshed tasks that use history. Use `scripts/publish.py` for authorized pushes with exact leases. A changed remote lease or target tip blocks publication until reassessed.

Return an assessment with outcome `no_op` or `published`, PR identity, reviewed and final heads and trees, target tip, commit count, boundary reasons, validation, recovery refs and publication receipts. A no-op must explain the whole series; an unchanged SHA is insufficient. Return this result to the caller so it can check coverage and CI within its saved budget. Do not claim the caller's iteration is complete.
