# Metadata readiness

Run these checks before committing local work, rebasing, pushing, editing the PR body, replying, or starting a review cycle. Missing derived metadata is a setup step; missing required configuration or unverifiable evidence blocks dependent work.

1. Run `python3 PLUGIN_ROOT/runtime/dk-pr-iter/scripts/preflight.py --cwd REPO --pr PR_URL` and save its JSON outside the repository. Require exit zero and `ready: true`. This checks `git`, `gh`, and only the hosts needed by selected bindings on the actual process PATH, installed configured reviewers, and completion prompt selection. Read and retain the returned completion prompt. Check the selected reviewers' own runtime prerequisites before starting work; the helper checks skill installation, not every adapter dependency. On SSH, the noninteractive PATH can differ from the login shell; use the verified installed tool directory for this run. Do not assume copying skills also copied tools, authentication, reviewer preferences, or private rules. Ask for a reviewer choice if none is configured; do not silently select one. A missing completion override uses the built-in default; an invalid override must be repaired or explicitly reset. This check validates tools and configuration only, not PR evidence, authentication, or push access.
2. Run `$dk-config --pr PR_URL refresh` and read the index and applicable source guidance. A cold or stale summary cache is rebuilt by refresh. After a startup-hook refresh failure, retry refresh once. If it still fails, read repository guidance directly, run `repo_rules.py --cwd REPO --pr PR_URL list` to read private rules and conflicts, and disclose that the private index may be stale. Continue only when the applicable rules can be established from those sources. Do not treat a failed read or malformed private configuration as an empty rule set.
3. Fetch the complete inline thread snapshot and the complete top-level conversation, linked issue scope, and current PR identity. Both feedback artifacts are required even if one has no items. Create or restore the run record and export verified decision context with `--local-decisions-file RUN_RECORD.json` before touching the branch. No existing decision cache is required: `context` fetches and builds it without publishing. An empty verified decision record is valid; failed analysis, partial fetches, conflicting sources, or invalid context are not. Preserve a corrupt decision cache or run record for recovery because it may contain local choices and publication history. Do not delete it or start a new record to bypass failures or reset cycle limits. Reconcile it with sources and live GitHub state before resuming.
4. When a called drafting skill returns `needs_discovery`, run its read-only discovery agent, submit the result, and use the returned `ready` context. Do not wait or poll for metadata that requires this work. If evidence changes during submission, refresh once and repeat discovery; if it changes again, report the unstable evidence. `unavailable` permits the skill's documented convention fallback, not invented PR scope, decisions, or successful review status. A broken derived convention cache may use direct source inspection as documented by the calling skill.

After a rebase, push, new decision, or PR body edit, refresh affected inline, top-level conversation, and decision artifacts before dependent classification or review. A new head invalidates earlier review and CI results. Preserve run counters across refreshes. A helper's nonzero exit, malformed output, or incomplete status must not become an empty successful result. Save helper output to a temporary file and replace the last verified artifact only after successful exit and validation.
