## Commit-series cleanup

Follow [waiting and communication](waiting-communication.md) during this stage.
Include its retained runtime path in every handoff; recipients read it and pass
it to their nested workers.

For an incomplete review with explicitly recorded human acceptance, omit `--review-complete`; the gate verifies exact-result acceptance without changing review status. Continue all cleanup/completion stages when that gate is clean, reporting accepted failures. Already-authorized thread resolution belongs to initial reply cleanup and does not wait for this gate.

Intermediate pushes for review and CI remain allowed. After the review and fix loop ends, assess each engineering completion criterion and save a current verification artifact using [the preparation verification contract](../../dk-pr-decisions/references/preparation.md#work-selection-and-completion-evidence). Record behavior, placement, test sufficiency, compatibility and cumulative complexity with rationale and fingerprinted evidence; review convergence alone does not satisfy these. Then refresh both feedback artifacts and account for every new or edited actionable item; route any remaining fix back through verification and any missing reply through the same reply agent's inline-then-top-level sequence. Run `scripts/completion.py --cwd REPO --pr PR_URL gate --stage review --start-head START_SHA --final-head REVIEWED_SHA --preparation-file PREPARATION.json --verification-file VERIFICATION.json --run-record RUN_RECORD.json --review-complete` (add `--actionable` when work remains). Require `gate: clean` before cleanup when the current preparation already has coverage. If refreshed discussion Decisions or operational evidence require equivalence assessment, hand off local assessment and candidate construction only; defer publication until the precheck and review gate below pass. Other review or CI failures remain blockers. This stage checks review readiness and fresh CI policy; it does not authorize completion.

Delegate the **full** series assessment and any rewrite through [dk-pr-split-commits](../../dk-pr-split-commits/procedure.md) to its **single worker**, even when iteration did not change the starting head. Give it ownership of assessment, planning, rewrite, verification, and the guarded cleanup push. Include the retained PLUGIN_ROOT, calling host, parent invocation path/token and DK_CLI_REFERENCE, preparation artifact path with both preparation_id and engineering_id, exact PR URL, repository path, run record path, reviewed head and tree, freshly verified target-branch tip, current decision context path and summary, test/CI evidence, and the workflow's waiting/message policy. State that iteration authorizes the local rewrite and exact guarded force-with-lease push needed for cleanup. Require `prepare --mode regroup` and the assessment artifact procedure in [the split worker instructions](../../dk-pr-split-commits/references/agent-procedure.md). The worker must preserve unrelated work and the reviewed final tree; the parent must not perform its Git mutations.

Before publishing the candidate (including a no-op), refresh both complete feedback snapshots and verified Decisions on the still-published reviewed head. Prepare and attach a ready engineering preparation in a separate isolated checkout pinned to that head; keep the candidate checkout clean. Compare against the original review with `run-state precheck-cleanup --head REVIEWED_SHA --candidate-head CANDIDATE_SHA --split-state GUARD_STATE.json`. Give the worker the run record and preparation paths for this coordination. The immutable receipt binds the active run, available cycle/attempt and session provenance, original review result, both preparations, candidate head/tree, base, lease, guard path and stable guard identity. Version-1 review results keep exact-scope and strict version-1 checks without inventing a session or attempt. A blocked, missing, mismatched or stale receipt leaves the candidate unpublished. Persisted disagreement cannot be reset by retrying. No reviewer runs and no cycle is allocated.

With that receipt, run the **review** gate above with `--cleanup-precheck RECEIPT.json` and the current preparation/verification pinned to `REVIEWED_SHA`. Require `gate: clean` and current CI before publication. This flag is restricted to `--stage review`; report review readiness, cleanup readiness and completion readiness separately. The worker passes `--cleanup-precheck RECEIPT.json` to `split_guard.py push` or the no-op `assess`. The guard revalidates the receipt immediately before acting. An uncertain push retains its receipt and recovery state; reconcile it without repushing.

Inspect every commit against the final diff. Preserve coherent existing boundaries; split mixed commits, fold fixups into the commits they repair, and reorder changes into coherent commits. One coherent commit is acceptable in regroup mode. An unchanged series requires recorded reasons explaining its boundaries and commit count. Record the worker handoff and its prepared state/recovery ref paths using existing run-record `event` entries. Require an assessment JSON outside the repository with PR identity, reviewed head/tree, target tip, final head, `no_op` or `published` outcome, commit count, and boundary reasons; record its absolute path in a `series-assessment:FINAL_SHA` event. A missing assessment, failed worker, interruption, uncertain publication, changed tree, remote head, or target tip leaves cleanup incomplete; preserve all recovery artifacts and report the blocker.

After a rewrite, run the existing single-process CI waiter on the **new** published head and save its result. An earlier head's green CI does not suffice. Apply the existing CI repair/rerun limits; a code repair or rebase invalidates the assessment and requires fresh review readiness and full series assessment before completion. Refresh both complete feedback snapshots and decision context against the final head after cleanup, including a no-op. Account for new or edited actionable work before proceeding. Never bypass cleanup because a custom completion prompt omits it.

Refresh and attach engineering preparation normally after cleanup, including a no-op. Keep the original preparation directory and its fingerprinted `evidence/` copies. For preparation v3 and review-result v3, follow the engineering-identity reuse rules in [the completion handoff](iteration-completion-handoff.md): a changed provenance ID alone does not require reconciliation at an unchanged head when the runtime-computed engineering ID and current coverage gate support reuse. A changed head, including a tree-equivalent rewrite, still requires the guarded final-head reconciliation path. Legacy v2 provenance keeps its stricter checks through its retained runtime. When the coverage gate requires comparison, run `run-state reconcile-review --head FINAL_SHA --series-assessment ASSESSMENT.json` through the retained CLI. This performs a fresh read-only semantic comparison directly with the original reviewed preparation, inspecting every analysis field, question/resolution, reviewer addendum and changed evidence source for new obligations. Only equivalent wording or synchronization changes qualify; PR, tree, base, body, ordered reviewers, effective descriptors and issue/instruction/rule fingerprints must match. Added discussion Decisions require an explicit independent mapping to an original decision or prepared boundary, citing retained original evidence and every verified discussion body. Removals, supersessions, changed human choices, new obligations and ambiguous mappings block coverage. Choices remain strict unless each source is an exact copy of that preparation’s validated Decisions context; those copies use the same decision rules and may change their top-level head. Worker instructions and completion criteria are independently assessed for unchanged engineering meaning. Raw fingerprints are preserved. Version-1 attestations retain their original strict restrictions. Prechecks are stored separately and never supply final reconciliation or completion coverage. A blocked receipt requires reporting its concrete reason or a fresh review within the existing budget. A persisted disagreement remains blocking for that result and evidence; concurrent approval, a byte-identical assessment copied to another path, or a byte-identical preparation retained in a new directory cannot override it. Exact original-preparation coverage and legacy strict coverage retain their ordinary checks. Provider errors and interrupted comparisons grant no coverage. Never reset the five-cycle budget. Identical intact evidence reuses the retained reconciliation, including after interruption; no reviewer executes during reconciliation. Refresh engineering verification for the current preparation before completion. Use the same fingerprinted cleanup assessment at the final live gate; later evidence changes invalidate reconciliation.

Refresh preparation after cleanup with `prepare --previous-preparation ACTIVE_PREPARATION.json`
using the complete final-head evidence package. An unchanged tree and governing inputs
preserve analysis without another preparation model call. Activate with the expected
parent ID and refresh engineering verification for the resulting preparation/head.
Keep the fifth cycle and immutable review results: identical-tree coverage is checked
by the existing scope gates; changed scope, instructions, base or tree still blocks.
