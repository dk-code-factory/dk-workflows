# Split PR commits

Spawn **one separate worker agent** for the entire request. Give it the user's exact request, PR or branch identifier, repository path, and any already settled decisions or constraints. For a `dk-pr-iter` cleanup handoff, also give it the reviewed head/tree, target tip, run record, decision context, and required assessment output path; use regroup mode even if the head is unchanged. Assign it ownership of the full workflow in [agent-procedure.md](references/agent-procedure.md): discovery, planning, local rewrite, message drafting, tests, verification, and any push or PR description edit the user requested. Tell it that others may be working in the repository, so it must preserve unrelated edits and never revert another agent's work. Do not split the series yourself or divide its stages among agents.

A request to split commits authorizes the worker's local history rewrite. If the user also asked to push the rewritten series, that request authorizes the guard's exact force-with-lease push; do not ask again. An iteration cleanup handoff authorizes the local rewrite and guarded exact force-with-lease push required for cleanup. The worker must ask the user only for a material choice or unsafe ownership condition identified by the procedure. Keep the same worker active through such a clarification rather than handing the rest to another agent.

Wait for the worker to finish. Report its verified commit series, test result, and push or PR edit status. For iteration cleanup, require the verified `no_op` or `published` assessment artifact and its boundary reasons; an unchanged head alone is insufficient. If it stops, report the concrete blocker without claiming the split is complete. Do not perform the worker's Git mutations in the parent agent.
