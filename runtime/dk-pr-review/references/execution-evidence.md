# Required independent-pass execution evidence

A configured provider's findings JSON does not establish that the independent
passes required by its installed skill ran. The runner retains mandatory native
host evidence separately from optional usage statistics and unchanged findings
JSON. It gates successful checkpoints, resumed coverage and final completion on
that evidence. Historical clean findings without it remain historical; they do
not become proof of unperformed work.

The current method profiles cover AD's Toolkit, Standards and Spec; Matpocock's
Standards and conditionally Spec; and the Claude PR Review Toolkit's code-reviewer. Explicit
`nested_review_roles` on custom bindings are also obligations. An empty override
cannot remove a known method's unconditional passes. Bundled default nested role
lists additionally include possible architecture recipients; packet preparation
alone is not execution proof. The supported AD 1.0.7 and Matpocock 1.0.1 method
profiles bind exact distributed Markdown source hashes on both native hosts. The
versionless Claude Toolkit profile also binds its exact Markdown sources. An
unknown version or changed procedure is unavailable method evidence, even when
all previously known roles ran; updating a profile is an explicit code change.

Codex AD Performance, Matpocock Spec, and Toolkit's test, comment, silent-failure,
type-design and simplifier passes have conditional applicability. Claude AD's
pinned method requires exactly three agents and has no Performance condition.
Matpocock permits skipping Spec only after explicit user confirmation that no
specification exists. The runner does not infer
semantic applicability from source regexes. The completed independent primary
pass (Codex AD Toolkit, Matpocock Standards or Toolkit code-reviewer) receives the installed procedure and
its linked criteria, and returns a structured applicability assessment in its
native result. It binds every conditional role's required flag and rationale to
the invocation, head, base and retained descriptor. This is independently
observed reviewer judgment, not deterministic source proof. Missing or malformed
assessment leaves applicability unknown unless every possible conditional pass
actually completed. A required flag always requires that pass's own native
completion. A parent summary cannot waive a specialist.

The executor requests Codex JSON events and Claude verbose stream JSON for these
reviews. Codex proof pairs a direct `collab_tool_call` spawn with a completed
agent result in the same native thread. Claude proof pairs a direct synchronous
Task/Agent tool use with its successful tool result in the same native session.
Each child prompt carries one exact `DK_REVIEW_PASS=<role>` marker. Multiple
markers, parent prose, launch acknowledgements, foreign sessions and unfinished
children do not establish coverage. Reactivating a child invalidates its earlier
completion until it completes again; ordinary closing cleanup preserves work.
Every observed marked child must finish, including repeated roles and corrections.

Optional telemetry continues reading Claude's unique final result envelope and
Codex's final cumulative root-turn usage without summing children or earlier
cumulative events. Native cached input is already included in input tokens.
Codex JSON mode does not expose the text-mode model header; absent another
explicit observation, model remains unknown. No provider calls or configuration
guesses are added to recover that measurement.

Private versioned records retain complete raw transport evidence, every bounded
JSON-correction attempt and the original provider result, including findings when
the execution gate blocks success. Their binding includes the immutable handoff
hash, PR revisions, response-budget/session owner, selected binding, installed
version, retained package digest, procedure and descriptor fingerprint. Checks
re-read all referenced hashes and recompute the assessment. Native model work is
not relaunched to obtain missing evidence, and correction/review budgets do not
change.

A complete supported native stream proving an omitted required pass is reported
as missing execution. Absent, malformed or unsupported host evidence and unknown
conditional applicability are unavailable evidence. Existing provider failure,
usage exhaustion and interruption handling remains distinct. Unknown host event
shapes fail closed. No live provider-compatibility or general recall claim follows
from offline transport regressions; unsupported host versions need a separately
authorized compatibility trial. Command providers declaring independent roles
currently have no trusted native-event adapter and therefore cannot claim their
completion; command providers without these obligations retain their contract.

Evidence lives under private workflow storage with private permissions. A storage
failure blocks acceptance. No transcripts, measured results or machine-specific
host files are distributed with the plugin.
