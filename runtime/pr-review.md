# Review another person's PR

Follow [simplification review](../docs/simplification.md). For each selected reviewer runner, pass the live owning workflow selector to plan/preflight and managed leaves; do not copy a composed list into invocation overrides. Re-select the live plan before completion. Verify maintainability recommendations for concrete benefit, behavior preservation and bounded scope without requiring a functional bug; fix workflows assess and implement justified recommendations through their existing stages. Preserve ordinary review coverage.

Before repository guidance reads, follow [repository instruction sources](../docs/instruction-sources.md). Follow all discovered instructions by default, or the saved explicit source override; do not require a source-choice question or onboarding; pass only selected source references as current rules, retaining excluded historical material as evidence. Refresh affected guidance and analysis when that choice changes.

Follow [private workflow reporting](../docs/private-reporting.md). Operational reports, blockers, diagnostics, handles and receipts go only to the invoking user or private caller, never into external text. Pass this governing contract downstream; publication permission does not authorize disclosure.

Read `dk-workflows:dk-pr-review` through [skill-owned configuration](../docs/skill-configuration.md). Its resolved `alternatives`, `tasks`, `finalizers`, `limits` and `permissions` govern selected invocations; follow list order and explicit parallel groups. Use the shared lifecycle for selected occurrences. The stages below supply applicability and acceptance rules, not hidden fallback invocations. Preserve evidence when selected work cannot satisfy a mandatory readiness requirement. Skip verification only when complete discovery has no candidates, recording that applicability decision; never claim an unperformed verification pass completed. Place custom work before or after discovery and verification directly in the task list; repeat the selected tasks when a new pass is needed within retained limits.

Find issues, verify them and post a review. This workflow does not authorize code fixes, commit rewrites, scope splits, description edits, feedback resolution or branch pushes. Use `dk-workflows:dk-pr-fix` only when explicitly asked to maintain the PR. Direct invocation permits posting verified findings under effective policy. Analysis-only instructions disable publication. Approval and merging each need explicit user permission or their own enabled saved policy, read directly under [workflow configuration](../docs/configuration.md). Permission to post findings grants neither.

Follow [preference retrieval and handoffs](../docs/preferences.md#workflow-handoffs-and-reuse) in `review` mode for discovery and independent finding verification. Select records against each task's paths, evaluate conditions, and pass full records with applicable paths and decisions. Capture that handoff in managed inputs. Refresh before claims, recording and final coverage checks when paths, relevant preferences or consumed condition context change, including before expanding scope. Reuse unchanged conditional decisions and refresh only affected work through task state.

Distinguish interruption recovery from renewed explicit review authorization under [retained budgets](../docs/task-state.md#retained-budgets). Automatic resume grants no cycles or publication permission. Use the authoritative [lifecycle and staged guidance](../docs/task-state.md#lifecycle-authority-and-guidance-loading) for every selected stage, preserving complete capture independently of deferred prose reads.

When entered from the publisher's [standalone-to-merge bridge](../docs/pr/ci-approval.md#standalone-review-followed-by-a-merge-request), preserve the original direct merge request and its exact authorization through all handoffs. Resume compact managed status and reuse current original results under their existing definitions and native evidence contracts. Complete missing or stale selected work and obtain CI approval evidence through the ordinary stages below; an unbound standalone report is context, never fabricated managed coverage. After evidence and execution approval, observe CI and return to the original publisher merge continuation. Do not stop at handing off or require the user to repeat an already authorized merge. Explicit policy, missing native execution/evidence or permissions, changed inputs, failed CI and unresolved review findings remain real blockers with their exact recovery step.

1. **Inspect and pin.** Resolve ownership through [PR routing](pr.md), selected invocations and reviewers through [configuration](../docs/configuration.md), and complete discussion through [shared evidence](../docs/pr/supplied-evidence.md). Resume compact managed status and retained alternatives references first. Preflight missing native alternatives work separately through `skill-preflight --skill dk-workflows:dk-pr-review --stage alternatives`, with the same options and upstream; preflight normal review/finalizer work at its own boundary. Save original instructions, settled and deferred scope, existing feedback, Decisions with sources, target, base, head and effective action policy. Direct invocation may review your PR, but never approve the authenticated account's own PR. Save the run and permissions in operational progress. Narrower new instructions revoke affected pending actions.
2. **Assess purpose and settle initial alternatives once per PR.** After initial inspection, follow the [shared assessment and alternatives contract](../docs/alternatives-review.md#incoming-workflow-once-per-pr). Use controller-injected assessment, then `dk-pr-alternatives`, with `alternatives.py plan --workflow review`. Inventory architecture throughout the branch, including inherited decisions, labeling each origin. Compare questionable decisions with the applicable persisted rubric and shared evaluation guidance. Include retaining current implementation and compare every option against the same pinned target revision without discounting work on the PR branch. Record separate per-decision comparisons and selections, then check their interactions. Default semi-manual asks only when automatic checks cannot settle a choice; automatic never prompts, manual requires explicit sourced choice, and pending choices block dependents. Resume unfinished work without repeating completed siblings. Review reports selected approaches without code or commit edits. Keep analysis private. Independently verify material design mismatches before authorized alternatives-only REQUEST_CHANGES publication through the existing journal; pass its operation to `plan --review-operation` and retain original required changes for ordinary review after later author commits. Same-head rejection stops before ordinary tasks and finalizers. Reuse initial analysis across commits and fresh sessions; changed governing scope or guidance requires explicit reassessment, while manual requests refresh requested analysis using unchanged shared assessment. New managed architectural inventory never accepts legacy whole-problem comparisons as its coverage. Current independent review, verification, CI, authorization and publication checks remain required. Preflight alternatives only until settled, ordinary tasks at review and finalizers at their own boundary. Disabled alternatives retains evidence.
3. **Find issues.** Apply [finding follow-ups](../docs/pr/finding-followups.md) to complete discussion and retained original findings, including reports from bots, people and earlier runs. Give discovery and verification historical candidates that may remain actionable; duplicate suppression must not hide them before current-head verification. Use the deterministic follow-up inspection for source/commit anchors and existing publication operations. When discovery or verification needs a new pass, check the remaining budget and save the cycle id. Complete preceding configured tasks before capturing final discovery inputs, refreshing inspection after their effects. Follow [the reviewer recipe](pr-reviewers.md) for the selected discovery invocation, normally `dk-workflows:dk-pr-reviewers-run`. Pin complete inputs and save reports and native handles. Manage claims and reuse through [task state](../docs/task-state.md). Use the saved `run` and `cycle` in prepare requests for discovery and verification in this pass. Changed source inputs require a new cycle; unchanged reuse uses none. Keep candidate findings separate from confirmed issues. Missing or incomplete required reports block a clean verdict. Preserve completed tasks. Follow [native handoffs](../docs/native-review.md).
4. **Verify independently.** Give a fresh native agent the candidate findings, original evidence, pinned source, governing scope and complete discussion. Assign verification only, without fixes or publication. Require it to challenge each claimed failure, inspect surrounding behavior and tests, reproduce when useful, check settled or intentional behavior, and check for prior fixes or reports. Return `confirmed`, `rejected` or `uncertain` for each finding, with source or reproduction evidence and severity. For historical candidates, separately recognize completed fixes and explicit accepted/deferred dispositions. Follow the finding-specific substantive-request and age procedure in [finding follow-ups](../docs/pr/finding-followups.md); recent or unknown age affects reminders only and never clears an unresolved finding from readiness gates; require finding-specific open-thread/current-request coverage for the unknown-anchor fallback. Confirmed findings also need a changed-line location. Preserve disagreements. No candidates means no verification invocation, but required discovery coverage must still be complete.

   Use the selected verification occurrence with responsibility `finding-verification` and the resolved skill identity under the [managed lifecycle](../docs/task-state.md). Capture the verification-only assignment, all governing references, original candidate outputs, configured controls and pinned context. Predeclare its complete native execution contract under [native handoffs](../docs/native-review.md). Use a fresh independent native agent; do not recursively invoke the full workflow. Failed/incomplete verification leaves candidates unverified; eligible same-cycle retries follow retained budgets. Uncertain findings block fork CI approval, PR approval and merging even when confirmed findings can be posted.

   Complete subsequent configured tasks in list order. Resume unfinished occurrences and retain unchanged completed results. Required failures block the next boundary. Refresh affected evidence after task effects; changed review inputs require another pass within the retained budget. Every task inherits this workflow's permissions, including its prohibition on fixes and branch pushes.
5. **Prepare and post.** Apply [finding follow-ups](../docs/pr/finding-followups.md) before suppressing previously reported findings. After at least one new PR commit since the latest substantive report/request, an independently confirmed actionable finding receives a targeted, source-linked fix request when posting is authorized. Reuse its original open inline thread or an equivalent open inline thread identified by independent verification, regardless of where the earlier finding was reported. Otherwise use ordinary changed-line review publication when authorized; never select a top-level reminder from the old report location. Count recent equivalent requests and original publication operations; unchanged reruns and formatting-only bot-summary edits must not cause another reminder. Exclude fixed, resolved, rejected, uncertain and explicitly accepted/deferred findings. Use the transient helper plan and existing publication journals, preserving uncertain-write reconciliation. For missing/rewritten anchors without equivalent open/current coverage, surface the freshly confirmed finding through an authorized changed-line review candidate; an old bot summary alone cannot suppress it. Pass effective route permissions; an unavailable or denied inline-thread reply route still requires assessing authorized review publication, without expanding permissions. Recover equivalent prepared/pending intents, including findings nested in ordinary review payloads, and count verified current-head receipts during discussion visibility lag. Suppress other duplicates already covered by current discussion or your reviews, including prior runs; never publish both a follow-up and a new duplicate inline finding. Post only confirmed actionable issues with evidence and changed-line locations. Honor the selected review publisher's `blocking_event` and `nonblocking_event` for completed verified findings (defaults `REQUEST_CHANGES` and `COMMENT`). Partial reviews use `COMMENT` for independently confirmed findings only, with coverage and verification blockers reported privately. Leave the general body empty unless a substantive repository summary was requested or the selected publisher's `include_summary` option is enabled. Withhold unverified findings or unsupported replies; never substitute operational diagnostics. Never report partial or uncertain coverage as clean. Before publication, refresh head, target, scope and discussion, then recapture affected tasks. Changes require reassessment and fresh verification. Cached findings do not authorize actions. Use the configured publisher, normally `dk-workflows:dk-pr-review-post`. Save exact payloads and operation receipts. Reconcile uncertain writes read-only before retrying.
6. **Approve fork CI when ready.** When selected in the finalizer list, run `dk-workflows:dk-ci-approve` after discovery, independent verification, finding dispositions and publication reconciliation finish, subject to resolved `permissions.approve_fork_ci` (default true). The default list places it before CI and optional PR approval/merge, independently of whether PR approval or merging is enabled. Analysis-only instructions disable mutations. Follow [CI approval evidence](../docs/pr/ci-approval.md): require another author's open non-draft PR, complete current review and necessary verification, no unresolved actionable or uncertain findings, reconciled publications and unchanged reviewed head, target and governing context. Read original outputs and recapture current task coverage; `ready:true` alone is insufficient. Successful CI and human PR approvals are not prerequisites. Save each journaled run/attempt receipt or the verified no-op. Permission failures, ambiguous associations and changed inputs block this action. Retain partial completion and reconcile uncertain operations read-only without resending. This permits CI execution only.
7. **Approve when authorized.** Require all selected reviewers and needed verification to be complete, no unresolved blocking or uncertain findings, and current CI for the exact head through `dk-workflows:dk-ci`. Recheck feedback, rules and coverage. Post `APPROVE` only when authorized and the authenticated actor differs from the author. If PR approval is disabled, skip this action after the independent fork CI approval boundary. Do not post an empty review just to mark progress.
8. **Merge when authorized.** Preserve an explicit merge instruction passed through `dk-workflows:dk-pr-iter`, including a combined checkout, iteration and merge request. It supplies permission with resolved `permissions.merge_pr.enabled:false`; approval remains a separate action. Require complete clean review and verification, current CI, satisfied repository review requirements, and an open, non-draft, mergeable PR at the reviewed head and target. Refresh live inputs and task status immediately before dispatch. Use `dk-workflows:dk-pr-publish` with `kind:merge-pr`, reviewed `head`, reviewed target `base` and authorized `merge_method` (`squash` or `merge`). The publisher checks current readiness and binds the request to the reviewed head. It does not bypass protection rules. Save the operation. After an uncertain outcome, reconcile the exact merge commit and actor. Changed source or an ambiguous outcome blocks further writes. Do not retry a merge.
9. **Report and resume.** Return reviewer and verification completion, finding dispositions, publication links, fork CI/PR approval and merge receipts or blockers. Check current governing inputs and affected coverage before claiming completion; report each requested action separately. Posting may be complete while approval or merging remains blocked. Use the shared lifecycle for targeted resume, original claims, retries, retained budgets and uncertain-publication recovery. Unchanged reruns must not duplicate external actions; automatic resume grants no allowance or publication permission.

Verification requires accepted mandatory [lifecycle completion checks](../docs/task-state.md#completion-checks) with its original verification agent.
